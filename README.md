# KLSE 潜力精选

扫描马来西亚全市场，把符合条件的少数股票直接解读给用户：**现在是否值得考虑、为什么入选、参考哪个价位、什么时候放弃原有判断**。首页默认最多3只，不用较弱信号凑数。

React + Vite 前端，Express + SQLite 后端，SSE 自动推送。行情来自 TradingView 马来西亚全市场快照，日线与数字代码映射来自 Yahoo Finance。免费接口可能延迟或限流；抓取时间不是交易所行情时间。

## 用户看到什么

- **放量潜力精选**：扫描上游马来西亚股票池，分别识别窄幅蓄势、放量转强、放量突破。当前精选必须成交量至少100万股、至少上一有成交交易日全天的2倍，平均成交额过线且价格未明显拉升。按相对20日均量、昨日量倍数、价格位置与均价状态排序，最多 `pick_count` 只（首页上限5只）。不会用形态或历史信号绕过当前成交量门槛。
- **已有信号持续追踪**：过去5个有成交交易日内最近信号，当前价格仍守住对应支撑且资料有效，会保留在追踪池；今日量倍数下降或已经拉升不会让此前信号消失。首页展示3只，其余可查询和翻页，详情说明未入选原因与候选排名。全部已发现信号写入独立持久表，区分信号日期和系统首次记录时间；历史回放不代表当时已实盘推荐。
- **覆盖检查**：公开上游数量、实际抓取数量、逐股分析数量、有效日线、缺映射/资料和失败重试名单。只有完整且无重复的分页扫描才能更新股票池；失效旧代码移出当前池，行情缺失的股票仍显示缺口。
- **蓄势解读**：直接显示整理上下沿、距离突破的位置、过去哪些日期出现量增价稳，以及跌破哪里时依据失效。相对昨日与相对20日均量分别说明，防止低昨日量制造虚假的异常放量印象。
- **成交量重点**：卡片和详情直接展示本次成交量、上一交易日全天量、放量倍数、增量与达标情况；详情用同一比例尺的条形图对比。成交量单位为股，100万股不是100万手。
- **短卡片与尾盘通报**：首页只显示量、倍数、一句判断和关键价位，完整分析折叠保留。交易日 MYT 16:00、16:30 各通报一次，从完整候选池重新筛选成交量**大于100万股、至少昨日全天3倍**且仍通过其他参与条件的股票，最多3只，无合格股票也明确通报。
- **次日表现**：固定保存每次通报的价格和成交量，下一交易日显示实际盘中或收盘变化，包括下跌；与通报参考价比较，不代表用户实际成交收益，也不保证隔天上涨。
- **成交活跃度**：精选还需通过最近20个完整交易日平均成交额下限（默认估算 RM 200,000，按每日收盘价乘成交量计算），并有本次有效成交。
- **直接分析**：给出“放量蓄势 · 尚未突破”“蓄势后初步突破”“已经拉升 · 等待回踩”等结论，附具体数值支持。量价条件无法证明主力吸筹或预测必涨。
- **单股详情**：参与参考、失效条件、60个交易日价格和成交量图、形态关键价位、资料时间。
- **我的关注**：用户自己的星标保存在浏览器；与系统的策略观察记录分开。
- **异动记录**：无需 Telegram，也能在网页看到放量、急涨、暴跌和形态异动。
- **Telegram**：`/top` 与网页共用简短解释。盘中精选、观察结果和异动提醒照常推送，16:00、16:30额外通报三倍量精选。管理设置可关闭 Telegram 尾盘推送、只在网页通报。
- **每半小时通报**：交易日MYT09:30–12:30、14:30–15:30每半小时固定通报当前精选，名单不变也发送；无合格股票也报告。16:00、16:30由更严格的尾盘通报接替，不再额外发一份两倍量定时通报。午休和16:30之后不发送半小时通报。固定通报不受盘中名单变化的去重规则影响；网页“半小时通报”保留与Telegram相同的价格、量和解释快照，并显示发送状态。

趋势、量能和双底仅是技术条件，没有覆盖财报、估值和公司公告。形态评分不是上涨概率；量度目标不保证达到。系统观察记录未模拟真实成交、费用与滑点，不能作为实盘收益。详见 [Investor.gov 历史表现说明](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-47)。

## 本地运行

推荐 Node.js 24（使用内置 `node:sqlite`）。

```sh
npm ci
cp .env.example .env
# 编辑 .env，填写随机的 ADMIN_TOKEN；Telegram 与 LLM 均可留空。
npm test
npm run build
npm start
```

访问 `http://localhost:8080`。Windows PowerShell 可用 `Copy-Item .env.example .env`。前端开发使用 `npm run dev`，另一个终端运行 `npm start`；Vite 将 `/api` 代理至8080。

服务会自动创建 `DATA_DIR`、`config.json` 与 SQLite 数据库；启动先返回已有缓存，后台扫描市场并补齐日线。冷启动的代码映射与历史回填可能需要较长时间，界面会显示资料状态。

### 离线界面验收

```sh
npm run build
npm run preview:fixture
```

访问 `http://localhost:8091`。股票明确标记为示例或历史回放，默认固定到本地日期的10:30测试时钟，使用独立临时数据库，不读取 `.env` 或生产数据库，也不能向外网发送通知。PowerShell 设置 `$env:PREVIEW_TIME='16:30:30'` 后启动，可验收两个通报页签和次日涨跌表格。管理员测试令牌是 `preview-only-token`。这是验收工具，不是生产启动方式。

## 部署

Render Blueprint 使用 `render.yaml`：Node24、`npm ci && npm test && npm run build`、`node server.js`、`/healthz`，并将数据库与配置写入 `/var/data` 持久盘。

在服务环境变量设置：

| 变量                                      | 用途                                                         |
| ----------------------------------------- | ------------------------------------------------------------ |
| `ADMIN_TOKEN`                             | 随机管理员令牌；未设置时所有管理写操作锁定，公开分析仍可访问 |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | 可选，Telegram 通知与指令                                    |
| `LLM_API_KEY`                             | 可选，自然语言查询使用 DeepSeek                              |
| `PUBLIC_URL`                              | Telegram 内指向网站的地址                                    |
| `DATA_DIR`                                | 持久化目录；默认为项目目录                                   |
| `PORT`                                    | 服务端口，默认8080                                           |

已有服务升级到2.0后，需要配置 `ADMIN_TOKEN` 才能修改网页设置。令牌通过 Authorization Bearer 请求头提交，设置窗口关闭后不保留。密钥不再通过 URL 参数写入或回显。真实 `.env`、配置和数据库不得提交到 Git。

## 筛选与时间口径

- 首页先检查百万股与两倍放量硬门槛，再核对现价是否同时高于昨收与MA5、资料是否新鲜、成交活跃度是否足够。放量下跌或价格未转强的股票等待量价配合；不必等20日涨幅达到15%才识别早期量价转强。
- `/screen` 强势筛选仍额外检查20个交易日涨幅范围、现价高于 MA5、MA5 > MA10 > MA15 > MA20，且同样保留百万股与两倍放量底线。
- 形态条件：两个相近低点、间隔与颈线高度约束、近期**完成日线**突破、当前报价守住颈线、评分和参考空间比达标。
- 窄幅蓄势路径不要求平稳股价已经高于昨收和MA5。此前10个有成交交易日高低价区间不超过12%，收盘区间不超过8%，首尾变化绝对值不超过8%。当前价格需守住下沿，且距此前最高收盘价的回落不超过8%。
- 平稳放量记录必须成交量过百万及两倍门槛，日变化 −1.5% 至 +3%，日内区间不超过8%，收盘位置至少位于日内区间45%处，排除明显放量下跌及宽幅震荡。此前10日至少出现一次这样的记录，或本次量达到此前20日均量1.5倍，才进入候选。
- “尚未突破”要求当前变化 −1.5% 至 +3%、价格未越过历史整理上沿；“初步突破”只允许上沿以上3%以内且当日涨幅小于8%。超过该范围或当日涨幅至少8%时，不列入提前布局精选。阈值是启发式观察条件，尚未经过大样本收益验证。
- 放量转强路径：最近5个有成交日收盘区间不超过12%、高低区间不超过20%，当前价格高于昨收和MA5、MA5不低于MA10、距离此前10日高点不超过10%、本次量至少20日均量1.2倍。放量突破路径要求越过此前10日高点，同样核对上涨和均价条件。可观测的当前高低价中，价格位置不得低于45%；所有路径保持百万股及两倍量底线。
- 转强/突破当天涨幅至少8%或超过历史压力3%时，只记录信号并追踪，不纳入当前参与精选。跌破最新信号支撑时退出有效追踪，不复活更旧的低支撑信号。
- 整理区、历史放量和20日均量全部由报价日期之前的数据确定。当前量仍须独立通过百万股及两倍门槛，旧放量记录不能替代今天达标。数据不足或过期的股票不会补入精选。
- [CNERGEN 案例与数据口径](docs/cnergen-volume-study.md)说明真实日期、量价数值及限制；回归测试确认10月2日已识别蓄势，10月5日大涨后退出提前布局条件。这是历史案例验证，不是实盘事前推荐或策略胜率。
- 同一份精选只比较最新市场快照日期的候选；午休时也不会把较早交易日的放量快照混入当天名单，不属于当前股票池的残留报价不参加排序。
- 形态目标固定为“颈线 + 形态高度”，达到目标后不会把目标向上移动以制造更好的空间。
- 日线回填在收盘前排除当天未完成 candle。盘中均线使用历史收盘加当前价格，成交量尚未定稿，结论会变化。
- 午休12:30–14:30保留当日接近上午收市时抓取的有效行情，并标注“上午快照”；不会仅因正常暂停扫描把全市场标为过期。上午提前停止更新、较早交易日及未来时间戳不能绕过新鲜度检查；14:30后恢复普通盘中新鲜度要求。
- 历史 `asof` 的涨幅、均线和昨日量都只使用参考日之前的数据，防止未来数据泄漏。
- 分钟/小时量采用累计快照差值，只在**同一连续交易时段**内覆盖足够历史且快照未过期时计算。午休、跨日或数据不足返回缺少资料，不进行错误拼接。新配置默认 `1d`，旧配置保留原时段。
- 常规时段使用 MYT 09:00–12:30、14:30–17:00；通过 `market_holidays` 配置交易所休市日期。这里不提供自动节假日日历，半日交易安排也需单独维护。[Bursa 交易手册](https://www.bursamalaysia.com/sites/5d809dcf39fba22790cad230/assets/6322ac3b5b711a2a5e7772a7/TradingManual_v5.2_final.pdf)。
- 休市时可保留最近完成交易日的精选，明确显示数据日期和快照状态；陈旧资料不作当前参与判断。

## 可靠性与管理权限

- 公共只读接口：`GET /api/state`、`/api/events`、`/api/stocks/:code`、`/api/watchlist`、`/api/screen`、`/api/coverage`、`/api/signals?q=BUSCAP&page=1`。信号池每页20条，查询具体代码另返回已保存的历史信号。
- 其余接口需 `Authorization: Bearer <ADMIN_TOKEN>`。管理员设置限制数值类型与范围；Telegram 普通群成员只能查询，群主/管理员才可改非敏感参数。
- `GET /api/broadcast-test` 永远只预览，不写告警去重、观察名单或发送队列；实际广播使用管理员 `POST /api/broadcast`。
- 信号去重、观察记录与 Telegram 发送队列在同一 SQLite 事务内提交；发送失败保留到队列，后续重试。Telegram 多段消息在部分发送成功后重试可能重复已送达的段落，不提供恰好一次交付保证。
- 尾盘时点强制完整扫描，要求本时点之后、最近3分钟内抓取的完整市场快照；旧资料或扫描失败不会写成“没有合格股票”。15秒检查一次，在时点后10分钟内重试，过时不补造旧时点通报。每天每个时点的快照与可选发送队列在同一事务保存，重启不会重复建立；Telegram 发送失败仍使用队列重试。
- 每个新告警先写入网页历史。SSE 首次连接立即返回状态，并有心跳、重连与浏览器缓存恢复。
- 观察天数按存储的真实交易日期计算，同一天扫描多次不增加天数。旧版受计天错误影响的到期记录会加注说明，不将其包装成策略胜率。
- 上游请求有超时；行情失败保留最近完整快照并显示错误。全市场按稳定代码分页检查总量、重复和提前结束；优先用上游ISIN中的数字代码映射Yahoo。日线按缺口增量回填，4个受限并发任务，失败保留旧资料，10分钟后重试，并尝试Yahoo备用主机。缺完整OHLC也重新回填；上市日数不足20天不能人为补足。日线回填与通知发送有锁防止重入。
- 开市轮询间隔限制1–5分钟，旧配置的30分钟自动按5分钟执行，避免过长扫描间隔错过短暂窗口。免费数据可能延迟、无成交或缺日线，覆盖对象是上游实际提供的股票/DR池，不能宣称已获得交易所全部证券的实时完整数据。
- [BUSCAP漏选审计与修复](docs/buscap-tracking-audit.md)记录源数据、遗漏原因、算法路径和回放限制。

## 配置

在网页的管理设置修改常用选项，或编辑持久目录中的 `config.json`。敏感凭据优先用环境变量。

| 参数                                  | 默认    | 含义                                               |
| ------------------------------------- | ------- | -------------------------------------------------- |
| `pick_count`                          | 3       | 精选和同时观察的目标数量，首页最多5只              |
| `final_briefing_on`                   | `true`  | MYT 交易日16:00与16:30固定通报，最多3只            |
| `half_hour_briefing_on`               | `true`  | MYT交易时段每半小时固定通报，名单未变也发送        |
| `final_briefing_telegram`             | `true`  | 已配置 Telegram 时同步定时通报；关闭后只显示网页   |
| `min_average_daily_value`             | 200000  | 最近20个完整交易日平均成交额估算下限，RM           |
| `poll_interval_minutes`               | 5       | 市场快照更新间隔，1–5分钟；旧的更慢配置按5分钟执行 |
| `window`                              | `1d`    | 看板成交量对比时段                                 |
| `screen_min_gain` / `screen_max_gain` | 15 / 25 | 20交易日涨幅范围，%                                |
| `screen_vol_mult`                     | 2       | 累计量与上一交易日全天量倍数                       |
| `screen_min_volume`                   | 1000000 | 精选成交量下限，股；不能低于100万                  |
| `db_min_score` / `db_min_rr`          | 70 / 1  | 形态匹配度和最小参考空间比                         |
| `db_fresh`                            | 2       | 突破允许的日线新鲜度                               |
| `price_thresholds`                    | `[]`    | 按价格范围设置网页放量告警阈值，空数组关闭该类提醒 |
| `cooldown_minutes`                    | 30      | 同股票放量告警冷却                                 |
| `watch_days`                          | 15      | 策略观察交易日数                                   |
| `market_holidays`                     | `[]`    | YYYY-MM-DD 休市日期列表                            |

Telegram：`/stock MAYBANK` 或 `/stock 1155` 查看直接分析，`/top` 查看当前少数精选，`/screen` 查看规则筛选，`/watch` 查看观察记录，`/stats` 查看规则结果，`/params` 查看设置，管理员 `/set pick_count 3` 修改参数。自然语言工具只能使用本地资料，不会自行补写新闻与财报。
